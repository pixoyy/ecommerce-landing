Peran Dokumen Ini

Dokumen ini mencakup repo essenseluxe-admin — Laravel monolith Blade/SSR yang berperan sebagai panel administrasi internal EssenseLuxe. Repo ini mengakses database server secara langsung (bukan melalui API Repo) dan mengelola seluruh operasi back-office: manajemen produk, stok, pesanan, pembayaran, pengiriman, promosi, user, role, dan otorisasi. Dokumen ini menyertakan ERD database server lengkap di Section 6 atas keputusan eksplisit tim — ERD yang sama juga terdapat di dokumen API Repo (EL-API-SPEC-001). Dokumen ini tidak mencakup UI yang diakses Customer.

2. Gambaran Dokumen

EssenseLuxe Admin Panel adalah antarmuka back-office berbasis web yang dibangun dengan Laravel Blade/SSR. Panel ini digunakan oleh staf internal EssenseLuxe untuk mengelola seluruh operasional platform: mulai dari master data produk hingga konfirmasi pembayaran dan tracking pengiriman.

Sistem otorisasi panel menggunakan RBAC berbasis tabel roles, modules, authorizations, dan authorization_types. Setiap Admin memiliki satu role, dan setiap role memiliki hak akses yang dikonfigurasi per modul dan per tipe aksi (create/read/update/delete). Superadmin adalah role dengan akses penuh yang di-seed langsung.

Admin Repo mengakses database server secara langsung — tidak melalui API Repo. Kedua repo berbagi database yang sama. Schema database didokumentasikan lengkap di Section 6 dokumen ini, dan juga tersedia di dokumen API Repo (EL-API-SPEC-001, Section 6). Jika ada perubahan schema, kedua dokumen harus diperbarui secara bersamaan.

Cakupan MVP v1 mencakup seluruh 19 modul operasional: Autentikasi Admin, Manajemen Role & Otorisasi, Manajemen Admin, Manajemen User, Manajemen Kategori, Manajemen Merek, Manajemen Produk, Manajemen Varian Produk, Manajemen Gudang, Manajemen Stok, Manajemen Promosi, Manajemen Akun Pembayaran, Manajemen Pesanan, Konfirmasi Pembayaran, Manajemen Pengiriman & Tracking, Monitoring Poin Reward, Moderasi Ulasan Produk, File Storage, dan Dashboard.

3. Glossarium

Istilah
Definisi
Admin
Staf internal EssenseLuxe dengan akses ke panel administrasi. Hak aksesnya ditentukan oleh role yang ditetapkan.
Audit Log
Catatan aktivitas Admin di panel (siapa, aksi apa, kapan). Lihat Section 7.6 masing-masing modul untuk status audit.
Authorization
Hak akses spesifik satu role terhadap satu modul dengan tipe aksi tertentu (create/read/update/delete).
Blade
Template engine bawaan Laravel yang merender HTML di sisi server (SSR). Tidak ada rendering client-side React/Vue.
Controller
Class Laravel yang menerima HTTP request dari Blade form, menjalankan logika bisnis, dan mengembalikan response/redirect.
Flash Message
Pesan notifikasi sementara yang muncul sekali setelah redirect menggunakan Laravel session flash.
Guard
Mekanisme Laravel untuk membedakan tipe pengguna yang terautentikasi. Admin menggunakan guard 'admin', Customer menggunakan guard 'web'.
is_active
Kolom TINYINT(1) yang menentukan apakah suatu entitas (produk, gudang, promosi, dll.) tampil/aktif di sistem.
Module Group
Pengelompokan navigasi panel admin. Setiap Module Group berisi beberapa Modules.
Override Price
Harga khusus varian produk selama periode promosi aktif, menggantikan harga normal.
RBAC
Role-Based Access Control — sistem kontrol akses berdasarkan role, bukan per-user individual.
Redirect
Response HTTP 302 yang mengarahkan browser ke URL lain setelah operasi (Post/Redirect/Get pattern).
Role
Kelompok hak akses yang ditetapkan ke satu atau lebih Admin.
SKU
Stock Keeping Unit — kode unik setiap varian produk untuk pelacakan stok.
Slug
Versi URL-friendly dari nama. Di-generate otomatis dari nama.
Snapshot
Data produk/harga yang disalin ke order_items saat checkout untuk menjaga konsistensi historis.
Soft Delete
Penghapusan data dengan mengisi kolom deleted_at — data tidak dihapus dari DB, hanya disembunyikan dari query normal.
SSR
Server-Side Rendering — HTML di-render penuh di server sebelum dikirim ke browser.
Superadmin
Role dengan akses penuh ke seluruh sistem. Di-seed langsung via database seeder.
Tracking Number
Nomor resi pengiriman dari kurir yang diinput Admin.
Warehouse Stock
Jumlah stok varian produk di gudang tertentu.

6. ERD / Skema Database (Server)

Catatan: ERD ini diduplikasi dari dokumen API Repo (EL-API-SPEC-001) atas permintaan eksplisit. Jika ada perubahan schema, kedua dokumen harus diperbarui secara bersamaan.

Engine Database: MySQL 8.x — InnoDB engine.

6.1 Konvensi Tipe Data Tim
Konsep
Konvensi Tim
Catatan
Boolean
TINYINT(1)
0 = false, 1 = true
Enum / status
ENUM MySQL native
Nilai exhaustive didaftar di kolom Deskripsi setiap tabel

TIMESTAMP NULL (deleted_at)
NULL = aktif; berisi timestamp = terhapus. Laravel SoftDeletes.

TIMESTAMP NULL
created_at, updated_at, deleted_at — semua TIMESTAMP NULL

Data terstruktur

7.5 Alur Fungsional Per Aksi

7.5.01 — Login Admin

Overview:
Admin mengisi form login. Controller mengautentikasi via guard 'admin'. Jika berhasil, sesi dibuat dan Admin diarahkan ke dashboard.

Step by Step:
Admin membuka /admin/login (middleware guest:admin — redirect ke dashboard jika sudah login).
Mengisi email dan password, klik 'Masuk'.
Controller validasi: email wajib + format valid, password wajib.
Jika validasi gagal → redirect back dengan errors dan input lama (kecuali password).
Panggil Auth::guard('admin')->attempt(['email' => $email, 'password' => $password]).
Jika gagal → redirect back dengan pesan 'Email atau password salah.'
Jika berhasil, cek status Admin: jika status = 0 → logout paksa, redirect dengan pesan 'Akun Anda tidak aktif.'
Perbarui last_login di tabel admins dengan timestamp saat ini.
Regenerasi session token (prevent session fixation).
Redirect ke /admin/dashboard.

Business Rules:
Email dicocokkan ke tabel admins — guard 'admin' harus dikonfigurasi di config/auth.php.
Admin status = 0 tidak bisa login meskipun password benar.
Admin soft-deleted tidak bisa login (Eloquent SoftDeletes mengecualikannya).
Rate limiting: 5 percobaan gagal per 15 menit per IP.

Error States:
Kondisi Error
Tampilan di UI
Penanganan
Validasi field gagal
Inline error di bawah field bermasalah
redirect()->back()->withErrors()->withInput()
Email/password salah
Alert merah: 'Email atau password salah.'
Pesan generik — tidak menyebutkan mana yang salah
Akun nonaktif
Alert merah: 'Akun Anda tidak aktif. Hubungi Superadmin.'
Logout paksa setelah attempt berhasil
Rate limit
Alert merah: 'Terlalu banyak percobaan. Coba lagi nanti.'
HTTP 429 — Laravel throttle

Kesalahan Terbesar:
Tidak mengonfigurasi guard 'admin' terpisah — Admin dan Customer berbagi sesi.
Tidak meregenerasi session setelah login — rentan session fixation attack.

7.5.02 — Logout Admin

Overview:
Admin klik Logout. Controller menghancurkan sesi guard 'admin' dan redirect ke halaman login.

$request->session()->invalidate() + regenerateToken().
Redirect /admin/login dengan flash 'Anda telah logout.'

7.5 Alur Fungsional Per Aksi

7.5.01 — Buat Shipment & Update Status

Overview:
Admin membuat data pengiriman setelah pembayaran dikonfirmasi, lalu secara bertahap memperbarui status. Setiap update status menghasilkan log tracking.

Step by Step (Buat Shipment):
Admin di /admin/orders/{id}, klik 'Buat Pengiriman'.
Mengisi: courier_name, shipping_cost. Warehouse_id otomatis dari orders.warehouse_id.
Dalam DB::transaction(): insert shipments (status=preparing) + insert shipment_tracking_logs (status=preparing, updated_by=admin_id).

Step by Step (Update Status ke Delivered):
Admin klik 'Update Status', pilih status baru, isi note dan location (opsional).
Cek alur: preparing → shipped → in_transit → delivered (tidak boleh mundur atau loncat).
Dalam DB::transaction():
  a. Update shipments.status.
  b. Insert shipment_tracking_logs.
  c. Jika delivered: update orders.status=delivered, shipments.delivered_at=now().
  d. Jika delivered dan order.point_earned > 0: kredit poin ke user_points, insert point_transactions.

Business Rules:
Satu pesanan hanya bisa memiliki satu shipment (UNIQUE order_id di shipments).
Status hanya bisa maju: preparing → shipped → in_transit → delivered.
Tracking number wajib diisi sebelum status bisa diubah ke shipped.
Konfirmasi delivered memicu penambahan poin reward ke Customer secara atomik.

Error States:
Kondisi Error
Tampilan di UI
Penanganan
Status mundur/loncat
Flash error: 'Perubahan status tidak valid.'
Validasi urutan status di Controller
Tracking number kosong saat shipped
Flash error: 'Nomor resi wajib diisi sebelum status shipped.'
Cek tracking_number sebelum update
Shipment sudah ada
Flash error: 'Pesanan ini sudah memiliki data pengiriman.'
Cek UNIQUE constraint order_id

Kesalahan Terbesar:
Tidak memberikan poin saat konfirmasi delivered — Customer tidak mendapatkan reward. Logika kredit poin harus dalam transaksi yang sama.

9.3 Struktur Route Group Admin

// routes/web.php
Route::prefix('admin')->name('admin.')->group(function () {

    Route::middleware('guest:admin')->group(function () {
        Route::get('login',  [AdminAuthController::class, 'showLogin'])->name('login');
        Route::post('login', [AdminAuthController::class, 'login']);
    });

    Route::middleware('auth:admin')->group(function () {
        Route::post('logout',   [AdminAuthController::class, 'logout'])->name('logout');
        Route::get('dashboard', [DashboardController::class, 'index'])->name('dashboard');

        // Superadmin-only
        Route::middleware('role:superadmin')->group(function () {
            Route::resource('roles',  RoleController::class);
            Route::resource('roles.authorizations', AuthorizationController::class);
            Route::resource('admins', AdminController::class);
        });

        // Admin+ (semua role)
        Route::resource('users',            UserController::class)->only(['index','show','destroy']);
        Route::resource('categories',       CategoryController::class);
        Route::resource('brands',           BrandController::class);
        Route::resource('products',         ProductController::class);
        Route::resource('products.variants',ProductVariantController::class);
        Route::resource('warehouses',       WarehouseController::class);
        Route::resource('stocks',           StockController::class)->only(['index','store']);
        Route::resource('promotions',       PromotionController::class);
        Route::resource('payment-accounts', PaymentAccountController::class);
        Route::resource('orders',           OrderController::class)->only(['index','show']);
        Route::post('orders/{order}/cancel',[OrderController::class,'cancel'])->name('orders.cancel');
        Route::resource('payments',         PaymentController::class)->only(['index','show']);
        Route::post('payments/{payment}/approve',[PaymentController::class,'approve'])->name('payments.approve');
        Route::post('payments/{payment}/reject', [PaymentController::class,'reject'])->name('payments.reject');
